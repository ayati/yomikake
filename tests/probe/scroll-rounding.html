章末判定の丸め誤差の実測

何を測るか
全画面画像ページ（img{width:100%;height:100%} の表紙・挿絵）は本文がちょうど 1 画面ぶんなので、 縦書きでは scrollWidth が 2 × clientWidth にぴったり一致するはず。
ところが 表示倍率が整数でない環境（Windows の 125%/150% 拡大表示、ブラウザのズーム）では 100vw が小数になり、切り上げの scrollWidth と切り捨ての clientWidth の差で 「余り」が 1px 残る。yomikake はこの 1px を「まだ本文が残っている」と読んで 真っ白なページを 1 枚挟んでいた（v2.24.1 で EDGE_EPS = 4 を入れて解消）。

手順: このページをブラウザで開くだけ。余りの列が 0 以外なら誤差が出ている。 ブラウザごと・ウィンドウ幅ごと・Ctrl+スクロールのズームごとに変わるので、 Chrome と Edge で違って見えるのは engine の差ではなく窓幅の丸めの偶然であることも確かめられる。
「標準」「中」はまず 0 になる — iframe 幅が max-width:900px / 1400px という整数で 止まるので小数が入り込まない。「狭」「なし」だけ窓幅そのものに依存するので誤差が出る。
